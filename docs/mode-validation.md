# pdn-soundmodem — mode validation report and provenance ledger

Living document. Tracks every mode string accepted by `ModemCatalog` (`src/Packet.SoundModem/Modems/ModemCatalog.cs`), how each has been validated (simulation and over-the-air), and — the point of this file — a dated, append-only ledger of *who/what proved a mode working*, with special attention to modes that were **broken and later fixed**, so a regression can always be traced back to the evidence that closed it the first time.

## Purpose and maintenance rule

This file exists because "does mode X work" is otherwise answered by grepping commit messages and hoping. Two things must stay true as the project moves:

1. **Every mode string in `ModemCatalog.KnownModes` appears in the matrix below**, with its current status. When a mode is added, removed, or renamed in the catalog, this file changes in the same PR (mirrors the `docs/plan.md` discipline).
2. **Every time a mode's validation status changes — especially broken → fixed, or working → regressed — append a dated entry to the [Validation ledger](#validation-ledger)** citing the exact commit hash, PR number, and/or issue number that did it, plus the evidence (mask figures, corpus decode counts, on-air BER). Do not edit or delete a prior ledger entry to "correct" it in place; append a new one and let the old one stand as the historical record. Where the provenance is genuinely not known, write **TBD** — never invent a commit, PR, or issue number.

Status legend used in the matrix:

- **working** — validated both in simulation/interop and confirmed over real RF (or, for corpus-based checks, against a real captured off-air/rig recording).
- **partial** — validated in simulation, but the on-air/interop result is mixed, marginal, or has a known open issue against it.
- **untested** — no meaningful validation recorded beyond the mode constructing (`ModemCatalog.Create` succeeding), or coverage is too thin to call it exercised.
- **not-yet-on-air** — solid simulation/interop validation; no real-RF attempt has been made yet.

- **2026-08-01 — backtracking deframer shipped (M0LTE.Il2p 0.1.2); c4fsk energy-gate removal attempted, measured, and retreated.** Toward closing the C4FSK acquisition-floor gap vs the NinoTNC (our 10–20 ms is the energy gate's assert latency; theirs is one 16-bit word), the deframer was made **backtracking**: every physical bit lands in a 16 KB ring, and any failed collection (header RS, body RS, CRC) rewinds the read cursor to one bit past the failed sync and re-hunts — bit-for-bit equivalent to never having false-locked, so a real frame swallowed by a garbage collection is always recovered (a 23-bit hunt warm-up after register clears guarantees termination). This removes the *deafness* rationale for gating bit streams — RS+CRC already guaranteed no false frame could emerge — and hardens **every** IL2P mode against idle-channel false-locks; shipped as 0.1.2 with recovery tests (frame inside a failed garbage header; frame inside a header-passing bogus body; frame after 100k bits of 75%-ones garbage) and bumped here with a modem-level idle-robustness test. **The c4fsk bit-path ungating itself is NOT landed**: four equalizer-lifecycle designs (rising/falling edge tap resets, a frozen-state "in preamble" oracle guard, input-power and decision-error adaptation sanity gates) each fixed one regime and measurably broke another — hermetic ISI bursts, txd0 short-preamble parity, or (worst) real-capture decode, where seconds of pre-burst idle-noise adaptation wrecked the corpus to 39/45 while every hermetic test stayed green. The coupling is real: the old gate was silently doing double duty as the equalizer's per-burst lifecycle authority. Retreated to the proven gated receiver (suite 796/796, corpus 45/45, sim unchanged); ungating is follow-up work whose registration should treat the equalizer lifecycle as the design problem, with the corpus + preamble-floor ladder + hermetic ISI + txd0 parity + after-noise cold start as the mandatory five-regime battery. The measured floors (2026-08-01 bench table) stand: c4fsk9600 10 ms, c4fsk19200 20 ms behind real NinoTNC preambles.

- **2026-08-02 (later still) — the 300 AFSK bank's reported frequency offset was a branch index, not a measurement; it is now a measurement, to ~2 Hz.** Building the ID-beacon ghosts on `afsk300` put the bank's `FrequencyOffsetHz` onto the waterfall for a second kind of frame, and probing it across the bank showed it was not a frequency at all. `Afsk300MultiModem` emitted the *first* branch to complete a frame and feeds branches in ascending order, so what reached the display was the lowest-centred branch that could still copy the signal — measured: true 0 → **−105**, true −140 and −70 → **−175** (clamped at the bottom branch), true +140 → +35, and the value moved with buffer framing (the same on-frequency signal read −35 through the daemon's device-sized blocks and −105 through one large buffer). Fine for deciding *whether* to emit, since the deduper is content-based and the bytes are identical whichever branch wins; wrong as the number an operator tunes by. #191's own test recorded the weakness honestly ("a lower bound on the true offset, not a measurement") rather than overclaiming — this replaces the weak contract with a real one.
  **The measurement was already being computed and thrown away.** The slicer's threshold is the midpoint of the mark and space envelopes, which is the discriminator's DC level, which is the carrier offset: summing the two tones cancels the ±shift and leaves `sin(4π·offset/rate)·cos(4π·shift/rate)`. `AfskDemodulator.CarrierOffsetHz` inverts that — no new filter, no per-sample cost, and derived from the same envelopes the bit decisions come from, so a frame that decoded has a settled reading by construction. Min/max envelopes rather than a mean is what makes it survive an HDLC preamble's 87.5 % mark duty cycle. Two things fell out of the probing: the chain mixes I from the sine and Q from the cosine (the transpose of the usual convention), so **the discriminator runs downward as frequency runs up** and the reading needed negating — never noticed before because the sign only picks which tone is mark, and mark assignment is free here (NRZI is polarity-agnostic; both IL2P receivers hunt sync in both polarities). And the reading compresses beyond ~±40 Hz where the discriminator clamp truncates the outer peak (±53 reads ±45, ±70 reads ±53), staying monotonic, which is all the branch ranking needs.
  `Afsk300MultiModem` now holds every branch's copy to the end of its chunk and emits the one with the smallest measured residual — the best-matched branch, which with 35 Hz spacing is never more than half a step out and so always reads in the honest zone; `branch + residual` is the answer. Cost: a frame waits up to 100 ms (one dedupe chunk) against frames that take seconds at 300 baud. **Measured after: −160 → −158.0, −140 → −138.5, −105 → −103.4, −70 → −68.5, −35 → −33.4, −17 → −15.9, 0 → +1.5, +17 → +18.0, +35 → +36.6, +70 → +71.5, +105 → +106.5, +140 → +141.5, +160 → +161.1** — worst error ~2 Hz across ±160 Hz, against up to 105 Hz before, and correct even at the two half-step points where no branch is "the" branch. A residual ~1.5 Hz bias is left uncharacterised; it is 0.5 % of the baud rate and below what any tuning decision turns on. `Afsk300MultiModemTests.The_Reported_Offset_Is_A_Measurement_Of_The_Signal` pins all thirteen points (a return to naming branches would show up as a ~35 Hz step); a lone `Afsk300Modem`, which reported no offset at all before, now reports one too. Decode counts are untouched — the off-air QRM fixture and every other afsk300/afsk1200 test passed unchanged through the change. **Not applied to `Afsk1200MultiModem`**, which has the identical "first branch wins" shape and would take the same fix: out of scope for this leg, and afsk1200 carries the WA8LMF corpus baseline, so it wants its own before/after rather than a drive-by.
